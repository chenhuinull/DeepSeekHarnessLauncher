# DeepSeek Harness 启动器

Windows 桌面启动器，提供启动/停止、更新、窗口始终置顶及可折叠运行日志。标题栏从左到右依次是关闭、最小化、置顶、更新、“日志”、启动/停止、状态灯，最后是鲸鱼图标——窗口按钮与鲸鱼图标本来各在两端（鲸鱼在左、最小化/关闭在右），按用户要求调换了位置，且关闭与最小化再互换一次（现在是关闭打头）、状态灯也从最左挪到了鲸鱼旁边、中间四个按钮再排成“置顶、更新、日志、启动/停止”（这样“启动/停止”紧挨着报告结果的状态灯）：“状态灯”悬停可查看当前状态说明，“日志”控制下方日志文本框，日志默认折叠；“置顶”开启时按钮为蓝色底，“更新”有新版本时为紫色底、可回退时为橙色底。双击鲸鱼图标可以把窗口折叠成只剩状态灯和鲸鱼图标的窄条（按住鲸鱼图标或标题栏空白处都能拖动窗口），再双击图标即可展开并恢复折叠前的日志状态；**按钮在鼠标松开时执行**（复查时发现的缺陷）：按下只记住按的是哪个按钮，松开时指针还在同一个按钮上才动作，按下后把指针拖开再松开就取消——早先是按下即执行，在“关闭”上按一下再把指针拖走照样会退出启动器；移动窗口不受影响，那是 `HTCAPTION`，由系统直接接管。折叠状态下点“日志”不会留下一个“待展开”的请求（芯片上没有日志面板），展开后日志仍是折叠的，不会自己弹开。折叠后左边是状态灯、右边是鲸鱼图标（与展开时“灯在鲸鱼左边”的顺序一致），窄条因此是 82px 而不是 84px。**折叠是从左到右的**：窗口矩形**完全不动**，折叠只是把窗口区域（region）从整个窗口缩成右端 76px 的芯片，所以灯和鲸鱼在屏幕上一动不动，正好还在鼠标指针下面；展开就是把区域去掉、交回 DWM。**DWM 的框和窗口区域不能共存**（踩过的坑）：一旦设了圆角偏好，DWM 就按整窗矩形画圆角边框、把区域**忽略掉**，于是折叠后整个窗口还是可见的（只有芯片有内容）；所以折叠时会把 DWM 的圆角偏好设为 `DWMWCP_DONOTROUND`、边框色设为 `DWMWA_COLOR_NONE`（框交给自绘的区域+边框），展开时再设回 `DWMWCP_ROUNDSMALL` 与 `#B8B8B8`。**折叠不再闪烁**（这一点量过）：早先的实现折叠时用 `SetWindowPos` 同时移动并缩放窗口，而**改变几何会立刻触发一次合成**——合成器手上还是上一帧的表面，于是先把“展开状态的标题栏”画在折叠后的位置上显示一帧（实测持续约 19ms），我们随后再画已经晚了一帧；只把重绘改成同步并不够（试过，仍然闪）。现在的做法是从根上不动几何：`Layout()` 里宽度恒定，只用 `SetWindowRgn` 换区域，并在同一次调用里 `InvalidateRect` + `UpdateWindow` 同步画完（`SetWindowRgn` 的 `bRedraw` 传 `FALSE`，免得系统拿旧表面多画一次）。验证方式是一个帧级探针（`.\version_parse_test.exe --fold`）：对真实启动器窗口发一次真实双击，用亚毫秒间隔从屏幕连续取帧并逐帧识别内容（关闭叉、按钮底板、边框像素），修之前能稳定抓到“折叠后仍画着展开内容”的那一帧，修完之后两个方向都只剩一帧画面（内容从头到尾就是目标状态）。回归检查里有对照：排队式重绘在同一次调用内绘制 0 次，`Layout()` 为 1 次。

**主窗口的形状完全由自己的 region + 外框决定**，不再向 DWM 申请圆角（否则折叠用的 region 与 DWM 的圆角会打架）；右键菜单仍然用 DWM 圆角，并且把菜单外框颜色设成和窗口外框一样，两者看起来仍是同一套。**最外边的边框色是 `#B8B8B8`**（中性灰，由 `windowBorderArgb` / `windowBorderColor` 两个常量给出，前者给窗口区域、后者给自绘外框与菜单的 DWM 边框色；改颜色只需改这两处）。外框分两段画：四个**边**用 GDI 的 `FillRect` 落在窗口最外那一圈像素上（整像素、无抗锯齿，所以四边各恰好 1px，屏幕实测 `left 1/1, right 1/1, top 1/1, bottom 1/1`，中间段每列恰好一个边框像素）；四个**角**用 GDI+ 的 `DrawArc`（抗锯齿，曲线平滑；GDI 的 `Arc` 在这个半径下是肉眼可见的台阶）。角弧的半径取**窗口区域圆角半径 + 1**，这样它整条落在区域内（画在区域边界上会被裁掉，四角就完全没有边框色），并且端点正好落在窗口自身的最外沿，与四条边无缝相接。

这里有一个 GDI 的坑和一个 DWM 的坑，都踩过、也都留了回归检查：
1. **`CreateRoundRectRgn` 生成的区域比给的矩形少一行一列**（它不含右、下边）。所以 `Layout()` 传的是 `width + 1` / `bottom + 1`；按窗口尺寸传的话，区域实际只有 343×47，最后一行一列不属于窗口，画在上面的边框会被裁掉 —— 表现正是"下面和右边的边框没了"（左右/上下只缺两边，是因为另外两边恰好落在区域内）。
2. **GDI+ 的描边会跨半像素**：1px 笔以路径为中心，会劈成相邻两列各半（渲染成 219 而非满色 184），四边落点还不一致；`AddArc` 还会把相邻圆弧用直线连起来，等于沿四边再描一道抗锯齿细线。因此边框不用 GDI+ 描边路径。

**折叠后的芯片是分层窗口（per-pixel alpha）**：轮廓、边框、灯、鲸鱼一次性画进一张 32 位 ARGB 位图交给合成器，所以圆角和轮廓的**抗锯齿是同一条曲线**。之前的做法是"窗口区域裁剪 + 自绘边框"，而区域边缘**没有抗锯齿**，无论边框怎么画都会差一点点（轮廓是硬台阶、边框够不到轮廓、四角时断时续）。窗口区域这条路留下的教训：`AddArc` 会把相邻圆弧用直线连起来、描边跨半像素、圆角半径与圆心要对齐到"最后一列/行"。

**模式切换不是原子的**：把窗口切成分层模式时，合成器会先用旧表面显示一帧 —— 这就是折叠闪烁。所以折叠的顺序是：**先用区域把窗口裁成芯片**（区域变化是原子的，而芯片那块区域在展开态里本来就是灯+鲸鱼+白底，看着一样）→ 再切分层并画上完美版本 → 最后撤掉区域（分层窗口的形状由 alpha 决定，区域那更大的圆角反倒会把芯片的圆角切掉）。展开则反过来：先退出分层（此时屏幕上是芯片，和刚才一样），再恢复区域并重绘。探针实测折叠/展开的中间帧内容都与最终一致（鲸鱼像素 182→173、173→展开态），没有旧画面、也没有整窗消失。**圆角统一为 3px**：按钮、窗口按钮底板、菜单高亮、日志框和窗口外框共用同一个 `cornerRadius`，窗口区域的椭圆尺寸取它的两倍，形状与描边曲率因此一致——此前外框是 6px、控件是 4px，看起来像两种形状。**状态灯的圆点直径 15px**（原 10px，居中画在 28px 的灯按钮里，四周留 6~7px 白边）；它由 `lampDotDiameter` 一个常量控制。窗口可拖动、最小化和关闭；启动器是工具窗口，不会出现在任务栏和 Alt+Tab 列表中。启动后窗口默认显示，并自动启动服务（若已有服务在运行则直接接管，不会重复启动）。托盘图标始终存在：左键单击显示/隐藏窗口，右键单击弹出菜单（显示/隐藏窗口、启动/停止服务、自动重启（勾选项，开启后运行中的状态灯变紫）、退出启动器）；最小化按钮把窗口收回托盘，关闭按钮退出启动器（Web 服务继续运行）。再次运行 exe 也能把它从托盘唤回（单实例保护会显示并激活已有窗口）。

窗口默认置顶，可通过标题栏的“置顶”按钮切换（开启时按钮为蓝色底）。日志区采用白底深色字。

启动器打开时位于主屏幕工作区中央。

日志默认收起；启动失败时自动展开，服务启动成功时自动收起。也可以随时点击标题栏的“日志”手动切换。日志框内部为白底深色字，且不自动换行；右侧和下方各有一根细滚动条，只画出滑块本身——没有轨道底色、没有两端箭头，长行可以直接横向拖动查看；平时不显示，鼠标停在日志框上或框内有选中内容时才出现（这两件事都由控件和滚动条自己的鼠标消息驱动，不需要轮询计时器）。这两根滚动条由启动器自己绘制、自己驱动：编辑控件不带系统滚动条样式，所以没有任何非客户区被占用，文字区因此比原来多出约 13×13 像素。滚动所需的数据也由启动器自己测量（行数、行高、首个可见行，以及**最宽一行的像素宽度**与横向偏移），拖动、滚轮和键盘翻页都可用，滚轮步长遵循系统设置；**不足一格的滚动量会累加**（复查时发现的缺陷）：精密滚轮和触控板一次只给 60、30 甚至 15（一格是 120），整除后是 0，早先这类设备上滚轮完全滚不动日志。日志用新宋体（NSimSun）13px：它同时自带中文与西文字形，汉字接近正方形且行间留 1px；之前用 Consolas 时汉字要靠字体链接借用别的字体、被塞进西文字格里，看起来偏扁。横向滚动条也因此按像素测量行宽——一个汉字顶两个西文字符宽。机器上没有新宋体时回退到 Consolas。两根滚动条是编辑控件的兄弟窗口，压在它上面，所以两者都带 `WS_CLIPSIBLINGS`——否则控件重绘时会盖到滚动条上。日志最多保留 5 万行，超出后自动丢弃最早的行。每条日志的分隔符加在行首、末尾不留换行，所以最新一行就贴在框底，框子底部不会空出一行的位置。按 Ctrl+A 全选；**全选之后再来的行会一起选进去**（选区末端原本就在文本末尾时，写入后延伸到新的末尾），所以“全选→过一会儿复制”拿到的是完整日志，而不是按下按键那一刻的长度。**一条日志就是一行**：文本里带进来的换行、回车、制表符在写入前会压成空格，否则编辑控件会在那里断行，而行数、裁剪用的行号和“最宽一行”都是按行记的；制表符还会被控件展开到下一个制表位，比测量出来的宽度更宽，横向滚动条就到不了行尾。新日志不会打断阅读：只有框内没有选中内容时，光标才停在末行并把视图留在底部（读者自己横向拖出来的位置会原样放回，不被这一下弹回最左）；一旦有选中内容，写入新行后会把选区原样放回、也不再滚到末尾，所以正在选的内容不会被下一行冲掉（这正是右键“复制”能用的前提）。拖选期间到达的日志先排队，松开鼠标再写入——写入需要先把光标移到文本末尾，而这会带走拖选的锚点，选区会在手势中途塌掉。右键菜单只有“复制”和“清除”两项：复制当前选中的内容（没有选中时该项为灰色），清除则清空日志框；剪切、粘贴等编辑项不会出现。

鲸鱼图标旁的状态点：绿色表示已启动（包括接管的外部服务），黄色表示未启动，红色表示未安装 DeepSeek Harness，紫色表示未启动且有更新，橙色表示进程还在但 Web 服务已经没有应答。悬停状态点可查看说明。

服务就绪后启动器每 5 秒仍会探测一次本地端口，并且**每次探测都写进日志**，正常的和失败的一视同仁（只看失败的话，就没法判断服务已经安静了多久）：正常时是「健康检查：正常（HTTP 200，3 ms）。」，没有应答时写明是「端口已无监听」还是「端口仍在监听但没有应答」、以及这是连续第几次失败，探到别的程序占着端口则写成「应答不是 DeepSeek Harness 页面（HTTP 502）」。连续 3 次没有应答（约 15 秒）就把状态灯变橙；服务恢复应答后自动变回绿色，日志里同时出现一条「恢复正常（HTTP 200，2 ms，此前连续 N 次无应答）」。进程本身退出仍然会立即反映为黄/紫/红。

**自动重启**（托盘右键菜单里的可勾选项，默认关闭，勾上后菜单显示 ✓）：开启后服务无响应、或意外退出、或启动失败时，启动器会自己把服务重新拉起来。两种失败路径（进程自己退出、健康检查发现它在装死）共用同一个计数器和同一条退避规则：第 1 次等 3 秒、第 2 次 6 秒、第 3 次 12 秒（上限 30 秒），连续 3 次都没成功就自动关掉这个开关并在日志里写明「自动重启已连续失败 3 次，已自动关闭该功能」，免得装坏了以后无限重启。如果某次启动成功并且稳定运行满 1 分钟，计数清零，之前那次故障不再计入配额——这个「已稳定」的时间戳**用完一次就作废**（复查时发现的缺陷）：留着它的话，之后每次失败都会看到「刚才那次稳定过」，计数每次都清零、永远停在 1，退避永远停在 3 秒，放弃规则也就永远不触发，「免得无限重启」形同虚设。手动点“启动”除了清零，还会取消已经排好的那次重试：否则用户手动启动、这次又失败之后，到点的定时器会再拉一次，而这一次不计入计数也不受放弃规则约束。

开启后**运行中的状态灯是紫色**（`#A855F7`）：紫色在这里表示“服务在跑、而且会自己回来”。它和“未启动，有更新”的紫色是同一个色值，但两者不可能同时出现——那个状态要求服务没有在运行。服务无响应时仍然是橙色，恢复成正常应答后才回到紫色。状态文案也随之变成「已启动，自动重启已开启」。

**设置会被记住**：开关写入 `%LOCALAPPDATA%\DeepSeekHarnessLauncher\settings.ini`（和 `server.log` 同一层目录，纯文本，可以直接看/改）：

```
topmost=1
autoRestart=0
```

“置顶”和“自动重启”两个开关的改变会立刻写盘，下次启动启动器时读回来（窗口创建前就读取，所以“上次关掉了置顶”这次不会再强行置顶）；托盘菜单的 ✓ 也按记住的值显示，自动重启为开时启动日志里会补一句说明。写入用“先写临时文件再替换”，中途失败不会把两个开关一起丢掉。文件不存在、键缺失或值读不懂时保持默认（置顶开、自动重启关），不认识的键会被忽略，方便以后增加设置项。

## 使用

发布原生 Win32 单文件版本需要 Windows 和 Visual Studio 的“使用 C++ 的桌面开发”组件。双击项目根目录的 `Build.cmd` 即可编译；命令行也可运行：

```powershell
.\Build.cmd --no-pause
```

目录结构：`Source\` 放源码（`launcher.cpp` 启动器本体、`build.ps1` 编译脚本、`launcher.rc` 图标资源、`version_parse_test.cpp` 回归检查），`Out\` 放编译产物，其中 `Out\DeepSeekHarnessLauncher.exe` 是直接可用的发布版，随源码一起入库。回归检查用 VS 开发者命令行编译后运行（`Source\version_parse_test.cpp` 顶部注释里有完整命令）：

```powershell
cl /nologo /std:c++20 /utf-8 /O1 /MT /EHsc /DUNICODE /D_UNICODE /Fe:version_parse_test.exe ^
   version_parse_test.cpp user32.lib gdi32.lib gdiplus.lib dwmapi.lib shell32.lib ole32.lib ^
   uuid.lib comctl32.lib iphlpapi.lib ws2_32.lib winhttp.lib bcrypt.lib advapi32.lib version.lib
.\version_parse_test.exe            # 逻辑与界面行为检查
.\version_parse_test.exe --screen   # 额外的屏幕级检查（会在右下角短暂显示一个小窗口）
.\version_parse_test.exe --discover # 查看本机的 Node.js / npm 探测结果
.\version_parse_test.exe --probe    # 立刻对正在运行的服务探测一次，打印日志里那一行
.\version_parse_test.exe --fold     # 帧级探针：对真实启动器双击折叠/展开，逐帧取屏并打印每帧内容（顺带存图到 %TEMP%）
```

首次点击“启动”会先寻找 `%LOCALAPPDATA%\DeepSeekHarnessLauncher\tools\node` 中的 Node.js 和 npm；本地没有时使用系统已安装的版本，两处都没有时由启动器自己下载 Windows x64 的 Node.js ZIP 并校验 SHA-256，解压到本地工具目录。下载在启动器进程内用 WinHTTP 完成，解压调用系统自带的 `tar.exe`，**不依赖 Windows PowerShell**。随后通过 npm 把官方 `@deepseek-ai/dsh` 及其依赖安装到 `%LOCALAPPDATA%\DeepSeekHarnessLauncher\runtime`，运行 `dsh web --no-open`。以后启动会复用这些本地文件，不需要重复下载。浏览器由启动器决定是否打开：读取 dsh 打印的地址后，先看浏览器里是否已经有 DeepSeek Harness 页面（按窗口标题精确匹配 `DeepSeek Harness`），已经打开就不重复开新标签页，没有才用默认浏览器打开带访问令牌的本地地址；地址随时可从运行日志复制。页面使用持久化的浏览器会话凭据，服务重启后已打开的页面依然可用。关闭启动器窗口不会停止 Web 服务；再次打开启动器会检测并接管仍在运行的服务，可通过“停止”按钮结束它。服务日志保存在 `%LOCALAPPDATA%\DeepSeekHarnessLauncher\server.log`。

启动器会检测并记录实际使用的 Node.js 与 npm 版本（例如“使用系统 Node.js v24.16.0 和 npm v11.17.0。”），而不是只判断文件是否存在。系统 Node.js 自带的 npm 往往比 PATH 上的全局 npm 旧（npm 11.13 不认识 `allow-scripts` 之类的 .npmrc 键，11.17 才认识），新旧 npm 对同一份配置和输出会有不同反应，因此会在私有运行时、`node.exe` 所在目录和 PATH 上所有目录中挑选**版本最高且与所选 Node.js 同属一个大版本**的 npm 并在日志中说明替换原因；不跨大版本升级，避免新 npm 要求比当前 Node.js 更新的运行时。

首次安装使用启动器内置的已知可用版本（Node.js `24.16.0`、`@deepseek-ai/dsh@0.1.5-rc.2`），因此同一份 exe 在任何机器上装出的结果一致。需要更新时点“更新”查询并安装 npm 上的最新版；服务成功启动过的版本会记入 `known-good.txt`，若新版本启动失败，“更新”按钮会变成橙色，一键装回上一个可用版本。

下载 Node.js 时依次尝试 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量、已启用的系统代理、直连，并会在 Node.js 官网、清华 TUNA、npmmirror 三个来源之间自动切换；如果系统设置里保存过代理但当前是关闭状态，全部失败后还会再试一次该地址（本地代理客户端未开启系统代理时很常见）。下载过程中日志会自动展开并显示百分比与已下载大小。压缩包只从与校验文件相同的来源下载，SHA-256 不一致或解压不完整时本次下载会被整体删除。

本地工具目录里的 Node.js 版本与启动器内置版本不一致时（例如升级了 exe），下次点击“启动”会自动把它更新到内置版本；更新失败只会记录一条日志并继续使用原有版本，不会因此无法启动。托管在 `%LOCALAPPDATA%\DeepSeekHarnessLauncher\tools\node` 的副本归启动器所有，系统已安装的 Node.js 不会被改动。

启动器按本地端口 3080 判断 Web 服务是否在运行，而不只依赖自己写下的进程记录。因此，即使服务是在终端里用 `npx @deepseek-ai/dsh web` 或 `dsh web` 手动启动的，启动器也会识别并接管它，状态显示“已启动”；点击“停止”结束这类外部服务前会弹出确认。反过来，如果端口被别的程序占用，启动会被取消并在日志中说明占用端口的进程，不会再生硬地拉一个必然因端口冲突而退出的服务。

“更新”按钮查询 npm 最新版本，20 秒未完成会结束查询并恢复按钮；发现新版后按钮底色变为紫色，再次点击即可更新（更新前需停止服务）。**只有远端确实更新才算“发现新版”**（复查时发现的缺陷）：早先只要版本字符串不同就点亮按钮，于是本机比 npm 的 `latest` 更新时（手工装过更新版本、或本地是 rc 而 latest 指向更早的稳定版）日志会写“发现新版本：新 → 旧”，一点就把装好的版本降回去；现在远端更低时不再提示，相同的数字仍然提示（rc 对上它自己的正式版、以及预发布后缀比不出大小的情形）。本机还没有 Node.js 与 npm 时，“更新”不会为了查询版本号而下载运行时，只会提示先点“启动”。服务成功启动过的版本会记入 `known-good.txt`，若新版本启动失败，按钮底色变为橙色，点击即装回上一个可用版本。

编译结果仅有 `Out\DeepSeekHarnessLauncher.exe`（源码在 `Source\`）。目标 Windows 电脑无需预装 .NET、MFC、Visual C++ 运行库、Node.js 或 PowerShell；若缺少 Node.js 和 npm，首次使用需要联网下载，解压依赖 Windows 10 1803 及以上自带的 `tar.exe`。
